# S3 AI 독립 실행 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend 없이 여수 4인·1박 2일 Agent의 생성·판단·실제 조회·일정·경비·관측 반환을 검증하고 JSON 런타임을 S2에 인계한다.

**Architecture:** `ai/` 안에 독립 Python 환경, 내부 DTO, 모델, 공급자, 도구, 실행기, CLI 평가를 둔다. `create_runtime(config)`가 모델과 직렬화 장치를 한 번 만들고, 작업마다 방 입력으로 새로운 도구 문맥을 구성한다. S2의 AgentPort는 JSON만 받으며 S3는 Backend나 서버를 실행 조건으로 삼지 않는다.

**Tech Stack:** Python, asyncio, httpx, pytest/pytest-asyncio, 선택 설치하는 Torch·Transformers·PEFT·safetensors, Qwen 베이스와 기존 judge LoRA.

**Spec:** [MVP 설계](../specs/2026-11-18-travel-agent-design.md), [계약 v0.2](../../contracts/travel-api.md), [공급자 조사](../../providers/place-data.md), [3세션 총괄](2026-11-18-three-session-plan.md).

## Global Constraints

- 이 문서는 향후 구현 절차다. 아래 생성·설치·테스트·외부 호출·Git 명령은 현재 실행하지 않는다.
- S1 FE, S2 BE, S3 AI의 최대 3개 세션을 동시에 시작한다. S3 내부 작업은 이 세션에서 진행한다.
- S3 쓰기 소유권은 `ai/**`, `docs/verification/ai.md`뿐이다. `frontend/`, `backend/`, 루트 manifest·환경 파일·README·검증표는 수정하지 않는다.
- [공통 계약](../../contracts/travel-api.md)과 [공통 예제](../../contracts/examples/README.md)는 읽기 전용이다. 변경 필요는 S2에 제안하고 단독 변경하지 않는다.
- `ai/contracts.py`의 TypedDict/Protocol은 AI 내부용이다. Backend/FastAPI/SQLite import, Backend HTTP 호출, Backend가 있어야 동작하는 테스트를 만들지 않는다.
- 국내 한 도시, 대표 데모 여수·4명·1박 2일. 자동차만 지원. 예약·결제·학습·복잡한 재시도 프레임워크는 범위 밖이다.
- JSON snake_case, 문자열 ID, 타임존 포함 ISO 8601, 날짜 YYYY-MM-DD, KRW 정수/미확인 null, 초·m, latitude/longitude를 따른다.
- 최근 메시지 20개 + 구조화된 방 상태 + 현재 작업의 도구 결과로 모델 입력 구성. 과거 메시지는 Backend가 넘긴 구조화 근거를 사용한다.
- 초기 실제 행동 선택 상한은 20회다. 단순 재검사마다 상한을 소모하거나 모든 작업에 20회 호출을 강제하지 않는다.
- 활동 구간은 Asia/Seoul 기본09:00–18:00, 체류시간 관광지60분·식사60분·카페40분은 변경 가능한 assumptions다.
- `submission/`, 대회 PDF, `TeamPredictor.predict()`의 후보 4개 계약은 보존한다. 서비스 후보 개수를 4개로 맞추거나 실패를 choice0 실행으로 바꾸지 않는다.
- 가격·시간·좌표는 실제 관측/사용자 확인값만 쓴다. fixture/fake 통과를 실제 API/Qwen 통과로 기록하지 않는다.
- 키가 없어도 A0·A2–A5 오프라인 작업을 계속한다. GPU와 live 공급자 probe는 S3가 단독 사용하고 인계 전 S1/S2가 중복 실행하지 않는다.
- 실행 요청 뒤 별도 worktree의 `work/ai`에서 개인 small-commits 스킬을 다시 읽는다. 실행 로직 약 300자 동작별로 실패 테스트→최소 구현→검증→선택 stage→커밋한다.
- 문서·설정은 자연스러운 단위로 작성하며, 약 300자를 맞추려고 코드를 압축하거나 대형 구현 뒤 기계적으로 커밋을 나누지 않는다.
- 구현 커밋은 AI 소유 경로만 포함한다. S2가 검증된 변경을 develop에 통합하고 push·master 대상 PR·전역 체크리스트 마감을 맡는다.
- 개인 `AGENTS.md`·`.local/skills/` 제외 규칙을 유지하며 강제 추가하지 않는다. 소유 밖 ignore 변경이 필요하면 S2에 전달한다.

| `ai/providers/{probe,apify,jeonnam,kakao,tourism}.py` | HTTP probe·정규화·선택 공급자 연결 |
| `ai/tools/{context,registry,places,routes,itinerary,costs}.py` | 작업별 참조 복원, 다섯 도구, 순수 계산 |
| `ai/eval/{cases.jsonl,replay.py}`, `ai/fixtures/`, `ai/tests/` | 독립 합성 대화·모드별 평가·테스트 |
| `ai/.venv/`, `ai/.artifacts/` | 로컬 환경·probe 요약·평가 출력·보존 해시. Git 산출물에서 제외 |
| `docs/verification/ai.md` | C01–C47 중 S3 증거·미검증·S2 인계 기록 |

- `create_runtime(config: dict) -> AgentRuntime`은 `ai/runtime.py`의 유일한 연결 생성점이다.
- config 키는 `model_backend`(`fake`/`local_qwen`), `provider_mode`(`fixture`/`live`), `base_model_path`, `adapter_path`, `env_file`이다.
- 이 생성 설정과 task/context의 config:TripConfig는 구별한다. 여행 날짜·활동 구간·거점은 작업 입력에서만 읽는다.
- `AgentRuntime.run(task: dict, emit_trace: Callable[[dict], Awaitable[None]]) -> dict`는 async이며 AgentInput→AgentResult JSON을 그대로 사용한다.
- `AgentRuntime.execute_tool(name: str, arguments: dict, context: dict) -> dict`, `AgentRuntime.aclose() -> None`도 async다.
- execute_tool context는 `{room_id,config,observations}`다. runtime은 장소 상세 요청에도 해당 방 관측과 config의 거점을 사용한다.
- 내부 `ModelBackend.generate_json(request: dict) -> dict`, `score_candidates(context: dict, candidates: list[dict]) -> list[float]`는 동기 경계를 유지한다.
- 내부 `ToolExecutor.execute(name: str, arguments: dict) -> dict`는 async 경계다. `run_agent(task, model, tools, emit_trace) -> AgentResult` 서명도 유지한다.
- AI가 Backend adapter를 만들지 않는다. S2가 FixtureAgentPort와 `backend/adapters/local_ai.py`의 지연 import/수명주기를 구현한다.
- AgentResult는 기반 버전을 되돌리고 변경 제안·plan_draft·observations를 반환한다. ID 배정·client_ref 치환·hash/version·원자 반영·공식 확인은 S2 책임이다.

## JSON 적합성 기준

- 입력 원본은 `docs/contracts/examples/agent-input.example.json`, 출력 원본은 `agent-result.example.json`이다. 파일 내용은 복사 후 AI 소유 fixture에서만 변형한다.
- AgentInput 필드는 run_id/room_id/base_versions/goal/recent_messages/members/config/constraints/items/questions/user_selection/current_plan/observations다.
- AgentResult 필드는 run_id/room_id/base_versions/constraint_proposals/support_observations/item_proposals/plan_draft/observations/conflicts/questions/completion/last_processed_message_id다.
- run_id/room_id/base_versions는 받은 값 그대로 반환한다. completion enum은 done/needs_input/unsupported만 허용한다.
- plan_draft에는 selected_item_ids/days/cost/validation/blocking_conflict_ids만 두고 item_snapshots·confirmation_target·content_hash·plan_revision은 생성하지 않는다.
- `edge-cases.json`은 최상위 patch가 배열 전체를 교체하는 규칙이다. unsupported/new-client-ref/selected-conflict를 AI 테스트로 검사하고 stale-result의 적용 거부는 S2 검사로 연결한다.
- 새 client_ref는 같은 AgentResult 안의 support_observations.item_id, questions.target_ref/related_item_ids, 계획 참조에서 일관되게 사용한다. 실제 ID 치환은 S2 한 곳에서 수행한다.
- 예제의 fixture Evidence는 status=api_observed여도 mode=fixture다. mode가 live가 아니면 실제 API 가격·시간 확보로 집계하지 않는다.
- `place-details.example.json`, `run-trace.example.json`도 필드/단위 비교에만 사용하며 실행 결과와 바이트 단위 동일성을 강제하지 않는다.
- trace에는 제품 상태 복원에 필요한 유일한 값을 두지 않는다. 장소/메뉴/경로 근거는 observations만으로 다시 사용할 수 있어야 한다.

- [ ] **6. 실제 평가:** 키·모델 준비 후 같은 replay를 `--model local_qwen --providers live --output ai/.artifacts/eval-live.json`로 실행한다. Qwen의 점수가 실제 호출을 결정하고 관측에 따라 다음 행동이 달라지는 trace를 확인한다.
- [ ] **7. 보존 검증:** 작업 시작/종료의 submission·대회 PDF 파일 해시 목록을 `ai/.artifacts/`에서 대조한다. 실제 공급자 응답 보관 조건을 지키고 비밀값·허용되지 않은 원문을 결과물에 넣지 않는다.
- [ ] **8. 인계 문서:** runtime config/서명/환경 활성화/CLI/fixtures/live 제약/공급자 선택/실측 자원·속도/모델 의존성 버전을 `ai/README.md`에 쓴다. GPU/live 독점 종료 시점을 S2에 알린다.
- [ ] **9. 근거 로그:** `docs/verification/ai.md`에 날짜·C번호·코드/모델 버전·mode·명령·관측·`ai/.artifacts/` 경로·판정을 남긴다. S3 범위 밖 항목은 S1/S2 확인 필요로 표시하고 전역 체크리스트를 직접 체크하지 않는다.

## 자체 검토·단계 마감

- 설계의 모델/공급자/도구/일정/경비/근거/Agent/trace/eval은 A0–A5에 대응한다. HTTP·저장·색상·전원 확인은 S2, 화면은 S1 소유로 명확히 남긴다.
- Review Focus 다섯 항목은 이름 있는 의미 테스트로 연결했다. 공통 예제 필드·runtime 서명·다섯 도구·JSON 출력의 일치가 인계 조건이다.
- 동결 계약에 구현상 빈틈이 발견되면 S2에 영향과 실패 예제를 보낸다. task config의 활동 구간은 내부 도구 문맥으로 전달하고 공개 build_itinerary 인자는 유지한다.
- 단계마다 완료 기능·검증 명령/결과·작은 커밋 범위·미완료 live 항목·다음 단계를 보고한다. S3가 push/PR을 했다고 주장하지 않고 S2 통합 상태와 구분한다.
- 현재 상태는 계획 작성이며 구현·설치·실제 API·모델 실행·Git 작업은 미실행이다. 사용자의 계획 검토와 구현 요청 뒤에만 위 체크를 실행한다.
