# 도구 준비조건·불확실성 개선 검증

- 검증일: 2026-11-19 (KST)
- 브랜치: `codex/qwen-judge-tool-execution`
- 구현 전 기준: `18ec906d2abda3e5d6b2013592d0bb380164c9ad`
- 설계: [도구별 준비조건·불확실성 표시·Qwen 선택 개선](../superpowers/specs/2026-11-19-tool-readiness-and-uncertainty-design.md)
- 제공 모델·LoRA·원본 judge와 기존 DB를 보존한다. 운영 서버는 이 작업에서 재시작하지 않았다.

## 구현 결과

기존 LangChain의 strict JSON Schema Structured Output과 Pydantic 검증을 확장했다. 보조 모델은 조회 목적·대상·조건·찬반·취소를 원문에 연결한다. 코드는 근거와 도구별 입력을 검증해 실제 후보만 구성한다. 제공 Qwen judge의 원시 채점과 argmax가 최종 행동을 선택하고, 실행기는 선택된 동일 도구·인자를 재검증해 실행한다. 채점 실패 시 다른 후보를 임의 실행하지 않는다.

- 단순 ‘찾아줘’는 위치 조회다. 방문 제안·지지·상세 수집을 자동 생성하지 않는다. 가격·영업시간은 별도의 상세 목적에 따라 조회한다.
- 복합 요청은 목적·대상별로 진행하며 완료·부분 실패·미지원·취소와 실제 응답을 저장한다. 한 요청의 종료가 다른 요청을 지우지 않는다.
- 과거 문맥으로 해소하지 못한 대상·경로 출발시각·지역에는 소유자가 답할 수 있는 질문을 제공한다. 해결·답변·취소 근거 없이 열린 질문을 삭제하지 않는다.
- 보조 모델의 일부 누락·잘못된 인용은 현재 원문의 명확한 표현에 한해 기존 검증을 거쳐 복원한다. 추출 보고서에 복원 이유를 남긴다. 원문에 없는 값이나 장소 ID를 만들지 않는다.
- 장소 매칭은 ID·도로명/지번·행정구역·좌표를 함께 확인한다. 실제 지점 모호성은 유지한다. 영업시간·가격 누락은 부분 결과로 보존한다.
- 일정과 비용은 독립적으로 가능한 부분을 계산한다. 미배치 방문·경로/영업시간 부족·미확인 통행료를 남긴다. 알려진 소계가 있어도 최종 합계가 불명확하면 `null`이다.
- 실제 선택된 계산 결과만 `partial_results` → `room.agent_results`로 발행한다. 입력 버전과 canonical 인자가 현재 상태와 맞아야 한다. `build_itinerary`의 일정 설정과 방문 입력 근거도 실제 채점 인자에 포함된다.
- trace 전송 대기 뒤에도 최신 취소·정정을 확인한다. 외부 조회 중 변경된 상태는 오래된 결과가 요청 완료·여행안·질문을 덮지 못하도록 반영 단계에서 검사한다.
- 지도·일정·상세에 언급됨/일부 지지/과반 지지/같은 여행안 확정을 텍스트와 색으로 구분한다. 조회·지지는 사람의 최종 확인을 대신하지 않는다. 이전 버전 표시는 당시 snapshot 기준을 유지한다.
- trace에서 예산 조건의 도메인 필드 `key`가 삭제되던 문제도 수정했다. 자격증명·비공개 추론·URL 비밀값 필터는 유지한다.

기존 저장 기록은 확장 필드가 없어도 읽는다. 계약 변경은 [travel-api v0.3](../contracts/travel-api.md)에 정리했다. 상세 응답을 받았다는 이유로 `validation=ready`나 전원 확인을 생략하지 않는다.

## 자동 회귀와 독립 검토

최종 커밋에 포함할 index만 별도 디렉터리에 복사해 테스트한다. 진행 중이던 다른 작업의 환경변수 관련 다섯 파일은 포함하지 않는다. Backend 테스트의 배포 환경 오염을 막기 위해 아래 네 값만 테스트 프로세스에 지정한다. `.env`는 수정하지 않는다.

```powershell
$env:COOKIE_SECURE='0'
$env:SERVE_FRONTEND='1'
$env:AGENT_MODE='fixture'
$env:TRACE_ENABLED='1'
<venv-python> -X utf8 -B -m pytest -c ai/pytest.ini ai/tests -q --tb=short
<venv-python> -X utf8 -B -m pytest -c backend/pytest.ini backend/tests -m 'integration or not integration' -q --tb=short
node --test frontend/tests/*.test.js
git diff --cached --check
```

| 최종 index 복사본 | 결과 |
| --- | --- |
| AI | 458 passed |
| Backend (integration 포함) | 222 passed |
| Frontend | 191 passed |
| 합계 | 871 passed, 0 failed |

Backend 명령은 기본 제외되는 integration 표식도 포함한다. 이 회귀 검증의 공급자와 judge 대역은 외부 호출 없는 계약·경계 검증이며, 실제 모델 검증과 구분한다.

독립 검토에서 실제 재현한 취소·대상별 오류·교차 지역 참조·문맥 누락·지도 표시 결함을 수정하고 다시 검토했다. 특히 보조 출력에서 취소 행이 빠져도 다른 장소의 요청을 취소하지 않고, 띄어쓰기 있는 두 번째 장소도 누락하지 않는 회귀를 포함한다. 잘린 이름·타 대상 필드·이전 완료 작업의 명령 표현을 새 요청의 근거로 사용하지 않는다.

## 실제 보조 모델 → Qwen → 도구 → Backend

외부 보조 모델 `gpt-6-luna`(검증 당시 기존 설정), 제공 Qwen2.5-1.5B와 LoRA, 실제 Kakao/Apify를 사용했다. 운영 DB 대신 매 실행마다 별도 SQLite·사용자·방을 만들고 기존 Backend 실행 등록/반영 경로를 사용했다. 공급자 조회는 실제 HTTP, 일정·비용은 실제 로컬 도구이며 fixture로 대체하지 않았다. 전체 trace와 원시 구조화 출력은 비밀값을 제거해 로컬 검증 자료로 보관했다.

| 시나리오 | 확인한 동작 |
| --- | --- |
| ‘돌산공원하고 자산공원 찾아줘.’ | 실제 검색 두 건, 두 장소 결과 표시. 공유 방문·찬성은 생성하지 않음 |
| ‘자산공원 입장료와 영업시간 알려줘. 내 예산은 15만원이야. 4시까지 귀가한다는 뜻은 아니야.’ | 실제 상세 조회가 같은 장소와 매칭. 미확인 가격·영업시간 유지. 본인 예산 150000을 본인 확인 대기로 저장하고 귀가시간 조건은 생성하지 않음 |
| ‘돌산공원에서 자산공원까지 지금 자동차 경로 알려줘.’ | 방향이 맞는 현재 경로 실제 조회, `departure_at=null` |
| ‘자산공원 가자. 확인된 비용부터 계산하고 가능한 일정도 보여줘.’ | 방문과 원문 작성자의 지지 보존. 미래 여행시각 경로를 별도 조회하고 일정·비용 두 도구 실행. 선결제 40000원과 미확인 비용 유지. 부분 결과를 저장하지만 여행안은 미확정 |
| 두 장소 조회를 한 회차로 제한 | 실제 검색 한 건 뒤 남은 대상이 저장됨 |
| ‘남은 장소 조회는 취소해줘.’ | 실제 Qwen이 소유 요청을 참조하는 응답 선택. 취소 저장 후 남은 대상의 공급자 호출 없음 |

각 회차에서 점수 배열의 argmax, 선택 후보의 도구명·인자, 실제 dispatch, Backend 저장 결과를 연결해 검증했다. 최종 실험 요약은 [검증 요약 JSON](2026-11-19-tool-readiness-and-uncertainty.summary.json)에 있다. 후보가 하나였던 회차는 단일 후보로 기록하며 유형 선택 정확도 근거로 해석하지 않는다. 회차 한도 뒤 미완료 요청은 기존 후속 실행으로 재개한다.

최종 실제 실행도 위 index 복사본에서 수행해 다른 작업의 환경변수 코드에 의존하지 않음을 확인했다. 테스트방은 `7fefff13cb1c10f93f7291397a970b79`이며 기존 방을 변경하지 않았다. 여섯 시나리오 모두 통과했다. 이 한 번의 측정은 성능 벤치마크가 아니며, 모델 로딩·설정 준비는 아래 처리 시간에 포함하지 않는다.

| 시나리오 | 처리 시간 | 보조 합계 | Qwen 합계 | 도구 합계 | 회차별 실제 후보 수 |
| --- | --- | --- | --- | --- | --- |
| 두 장소 위치 | 6.60s | 4.83s | 1.43s | 0.32s | 2, 1 |
| 상세·예산 | 57.69s | 2.99s | 0.52s | 54.17s | 1 |
| 현재 경로 | 4.53s | 3.70s | 0.63s | 0.18s | 1 |
| 부분 일정·비용 | 10.12s | 3.53s | 6.36s | 0.13s | 2, 1, 2, 1 |

상세 조회의 지연 대부분은 실제 공급자 수집이었다. 이 결과를 보조 모델이나 Qwen의 지연으로 합산해 해석하지 않는다. 두 유효 검색 중 하나를 선택한 성공과 단일 유효 후보를 선택한 성공도 유형 오선택을 판별하는 진단과 분리한다.

초기 실제 실행에서는 보조 모델이 예산을 요약에만 쓰거나, 복합 조회를 원문과 다른 짧은 인용으로 출력하는 문제가 재현됐다. 엄격한 검증을 제거하는 대신 원문 기반 복원과 목적·대상별 누락 검사를 추가했다. 저장한 실제 출력은 `ai/fixtures/auxiliary-compound-lookup-replay.json`의 외부 호출 없는 회귀에도 사용한다. 이 복원이 모든 자연어의 완전한 추출을 보장하지는 않는다.

## Qwen 입력 비교와 잔여 한계

제공 weight·LoRA·`submission/judge.py`·yes/no logit 차이·argmax는 변경하지 않았다. 같은 12개 선택된 진단 입력/후보에 세 입력 방식을 적용했다.

| 방식 | 미리 정한 기대 선택과 일치 |
| --- | --- |
| 기존 간단한 도구 설명 + JSON | 5/12 |
| 상세 도구 스키마 + JSON | 6/12 |
| 상세 도구 스키마 + 읽기 쉬운 패킷 | 6/12 |

총 36회는 고의로 부적절한 후보를 섞은 진단이다. 실제 서비스 정확도·언어별 성능 추정치가 아니다. 네 응답 유형 경쟁과 여러 도구 경쟁, 한국어/영어 입력을 구분했다. 읽기 쉬운 패킷에서 일부 경로 선택은 개선됐지만 영어 대상 부족 질문은 퇴행해, 제품 기본값은 JSON을 유지했다. 원시 점수는 확률이 아니다.

영어 학습이나 제공 도구와의 차이가 전혀 문제없다고 결론 내리지 않는다. 미지원/직접 응답 등 오선택이 진단에 남았다. 원문에 맞는 유효 후보만 생성하는 경계가 필요하며, 여섯 실제 시나리오의 성공도 임의 대화 전체의 품질 보장은 아니다. 점수 보정·정답 삽입·차순위 강제 실행으로 결과를 성공 처리하지 않았다.

## 화면과 보존 확인

실제 검증 DB의 별도 읽기 전용 복사본을 loopback 8119에서 브라우저로 확인했다. 테스트 전용 쿠키를 사용했으며 운영 로그인은 바꾸지 않았다. 요청별 실제 응답·취소 이력, 본인 확인 예산, 알려진 소계/미확인 최종 비용, 부분 일정, 비활성 확정 버튼과 장소 상세의 ‘영업시간 미확인’/‘휴일 정보 미확인’을 확인했다. 원시 빈 배열/JSON을 안내 문구로 노출하던 문제를 수정했다.

이 별도 origin에서 지도 SDK가 로드되지 않아 좌표·서버 경로 fallback과 상태 범례를 확인했다. 실제 지도 SDK 화면을 검증했다고 보고하지 않는다. 지도 agreement·지원 변경·과거 snapshot 갱신은 adapter/DOM 회귀에서 확인한다. 임시 화면 서버는 검증 후 종료한다.
