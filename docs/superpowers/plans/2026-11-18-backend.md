# Backend·통합 조정 Implementation Plan — S2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development 또는 superpowers:executing-plans로 아래 체크 단위를 실행한다. 이 문서는 구현 요청 전 계획이며 현재 실행 결과가 아니다.

**Goal:** FE·AI 구현 없이 계정·방·대화·공동 상태·확인·SSE를 완성하고, 이후 두 세션의 산출물을 JSON 경계로 연결한다.

**Architecture:** FastAPI·SQLite Backend는 `AgentPort`에만 의존한다. Backend 소유 `FixtureAgentPort`로 독립 검증을 끝낸 뒤 `LocalAIBridge`에서만 AI runtime을 지연 import한다. S2가 최종 통합과 공통 문서 반영을 조정한다.

**Tech Stack:** Python, FastAPI, Pydantic, SQLite, pytest, HTTP 테스트 클라이언트. 독립 Backend 환경에는 torch·Transformers·PEFT·공급자 SDK를 설치하지 않는다.

**Spec:** [MVP 설계](../specs/2026-11-18-travel-agent-design.md), [API 계약 v0.2](../../contracts/travel-api.md), [3세션 실행 계획](2026-11-18-three-session-plan.md), [공통 JSON 예제](../../contracts/examples/README.md).

## Global Constraints

- 세션은 정확히 S1 FE, S2 BE+통합 조정, S3 AI다. 이 문서는 S2만 실행한다. 과거 [BE·AI 합본](2026-11-18-backend-ai.md)의 소유권·선행 순서는 이 계획으로 대체한다.
- 국내 한 도시, 대표 데모 여수·4명·1박 2일. 자동차만 지원. 숙소·출발/귀가 지점·숙박/장거리 교통비는 사용자 입력이다.
- 전체 여행 1인당 예산, 기지출 포함, 공용 비용 균등 분담이라는 제품 계약은 유지한다. 계산 구현은 S3가 소유한다.
- 노랑 기준은 `floor(N/2)+1`, 초록은 같은 불변 확인 대상의 전원 확인과 검증 통과다. 개인 필수 조건은 다수결로 완화하지 않는다.
- JSON snake_case, 문자열 ID, 타임존 포함 ISO 8601, KRW 정수/미확인 null, 이동 초·m, latitude/longitude를 유지한다.
- HTTP 경로·요청/응답·상태 코드·SSE event/seq는 계약 §§3–4 그대로다. 사용자는 같은 origin cookie로 식별한다.
- `backend/`는 `ai/contracts.py`를 import하지 않는다. AI 내부 타입을 공용 타입으로 이동시키거나 Backend 타입 생성을 S3에 요청하지 않는다.
- S2는 모델·공급자·추출·행동 선택·시간표·경비 알고리즘과 해당 테스트를 작성하거나 복제하지 않는다. `ai/**`, `frontend/**`, `submission/**`는 수정하지 않는다.
- 이 계획의 설치·테스트·Git·연결 명령은 향후 구현 때 실행한다. 문서 작성만으로 제품 파일 생성·의존성 설치·모델/API 실행·Git 초기화·커밋·push·PR을 시작하지 않는다.
- 구현 시작·재개·각 작은 단위·단계 마감에 로컬 `AGENTS.md`와 `.local/skills/trip-agent-small-commits/SKILL.md`를 적용한다. 실행 로직 약 300자 내외의 자연스러운 동작마다 검증하고 커밋한다.
- 설정·문구·문서는 300자 제한 대상이 아니지만, 파일명과 무관하게 실행 표현식·분기·호출·테스트 로직은 기준을 적용한다. Task 하나를 대형 커밋 하나로 처리하지 않는다.
- 향후 격리 작업은 S2 전용 `work/be` worktree에서 한다. 개인 파일은 Git 제외라 새 worktree에 자동 제공되지 않으므로 원본 위치의 규칙을 읽고 로컬 제외 상태를 먼저 확인한다.
- 다른 세션은 자신의 브랜치에서 검증된 커밋을 인계한다. `develop`으로 모으는 작업·원격 push·`master <- develop` PR 갱신은 S2 통합 담당자만 수행하며 자동 merge하지 않는다.

## 환경과 명령 기준

모든 명령은 저장소 루트에서 실행한다. 아래 환경 준비는 B1의 독립 Backend 검증에 포함되며 현재 실행하지 않는다.

```powershell
py -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
backend/.venv/Scripts/python.exe -m pytest -c backend/pytest.ini backend/tests -q
backend/.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

`backend/pytest.ini`는 Backend 테스트와 독립 실행 옵션만 설정한다. `integration` marker를 등록하고 기본 선택은 `-m "not integration"`으로 둔다. 실제 runtime을 쓰는 테스트는 명시적 통합 실행에만 선택하고 import도 실행 시점까지 미룬다. 수집이 `ai/tests`나 AI 의존성 로딩으로 확장되지 않는다. 설정은 `backend/.env.example`의 키 이름·로컬 경로 예시를 복사해 사용하며 기본 데이터 경로는 `backend/.data/`다.

기본 앱은 fixture 모드이며 표시용 근거의 `mode=fixture`를 보존한다. 실제 연결 환경은 B5에서 S3의 설치 안내를 받아 별도로 준비한다. 독립 완료를 위해 AI requirements 설치나 로컬 가중치 준비를 요구하지 않는다.

## JSON 경계와 독립 인계

아래 경계는 계약 §5의 복사 요약이며 새 필드를 추가하는 별도 계약이 아니다. Python 객체·DB 연결·HTTP 요청·상대 모듈 클래스는 전달하지 않는다.

| 경계 | Backend가 보장할 값 |
|---|---|
| AgentInput 식별 | run_id, room_id, base_versions, goal |
| AgentInput 사람·입력 | recent_messages, members, config, constraints, items, questions |
| AgentInput 기존 결과 | user_selection, current_plan, observations |
| AgentResult 식별 | run_id, room_id, base_versions |
| AgentResult 제안 | constraint_proposals, support_observations, item_proposals, plan_draft |
| AgentResult 근거·완료 | observations, conflicts, questions, completion, last_processed_message_id |
| 직접 도구 context | room_id, config, observations; 요청마다 해당 방 값으로 구성 |

Backend는 source message ID의 방·저자와 기존 대상 ID를 검증하고, 새 제안의 client_ref를 실제 ID로 바꾼다. 자연어가 어떤 의미인지 다시 추출하거나 AI의 도구/모델 선택을 재판단하지 않는다.

통합 전 인계에는 설치 명령, 전체 독립 테스트 명령, JSON 예제 적합성 결과, 포트 교체 방법, 미검증 live 항목을 포함한다. S1은 HTTP/SSE만, S3는 JSON AgentPort만 알면 인계를 받을 수 있어야 한다.
