# feat/front 화면 통합 설계

사용자가 승인한 비교 결과를 바탕으로 최신 develop에서 통합한다. React 도입 없이 바닐라 JavaScript 모듈과 FastAPI를 유지한다. feat/front의 로그인·회원가입, 내 여행방 목록과 생성/참가, 조건 사이드바, 떠 있는 채팅창, 최초 설정 팝업, 장소 검색 구성을 채택한다.

기존 develop의 Vercel 정적 빌드와 같은 출처 API 프록시, Node24, 지도 공개 키 주입, COOKIE_SECURE 설정을 유지한다. 방 목록·이메일 초대·방장 삭제/이름 변경 API와 owner 정보, 날짜 선택 전 생성 흐름을 추가한다. 선택 전 날짜는 AI 호출 경계에서만 하루 일정으로 보완하고 원본 설정은 그대로 둔다. 최신 develop `e6f4965`의 판단·실제 도구 실행·요청별 결과 흐름을 기준으로 AI 파일은 그대로 보존하고, 백엔드 작업 경계의 `run_current/is_current`와 삭제 후 결과·기록 재생성 방지를 결합한다.

채팅과 결정 입력의 작성 중 내용, 전송 중 새 초안, 누적 대화, 중복 제출 방지,401/409 복구, fixture/LIVE 세션 분리를 보존한다. 날짜별 동선·번호 지도·조회 실패 재시도도 새 화면 안에 연결한다. 로그인과 회원가입은 분리하며 로그인 후 방 선택 화면을 거친다.

첨부 FE 보존 조건에 따라 요청 원문·작성자·진행/실패/취소·응답·결과/대화 링크를 표시한다. 부분 일정과 비용은 네 입력 버전이 모두 현재와 일치할 때만 별도 표시하며, 미확인 금액·관측은0으로 바꾸지 않는다. 목록·지도·상세는 같은 동의 판정을 사용하고 과거 확정안에 새 버전의 지지를 붙이지 않는다. 대상 장소·출발 시각·지역 질문과 기존 답변 DTO를 유지한다. 지도 좌표는 `location_only=true`, 사용자가 여는 장소 상세는 일반 GET으로 분리한다. 만료된 부분 결과의 선택과 늦은 응답을 제거한다. 공유 질문은 열린 상태에서 한 번만 답할 수 있다.

검증은 FE 전체 테스트, BE/AI 회귀 테스트, Vercel 빌드 산출물과 실제 쿠키 API를 대상으로 한다. 브라우저에서 회원가입·로그인→방 생성·초대 코드 참가→메인, 새로고침·로그아웃·잘못된 입력을 확인한다. 실제 모델 및 공급자 호출은 기존 프로세스를 건드리지 않고 fixture/fake 경계로 회귀 확인한다.

사용자 지시에 따라300자 제한과 단계별 커밋을 적용하지 않는다. 전체 완료 후 단일 커밋을 만들고, 원격 develop이 진행됐으면 변경을 보존해 재검증한 뒤 강제 push 없이 전달한다.
